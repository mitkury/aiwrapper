# Proposals

Apply the [shared proposal rules](../../airul/rules/how-to-write-proposals.md).
Write proposals under `docs/dev/proposals/` and link active work from the
[documentation index](../../README.md).

This is a public repository. Keep private downstream application names, plans,
paths and implementation details out of code, tests, docs and commit messages.
Describe reusable library behavior without identifying private consumers.

A proposal records proposed work; it does not itself authorize implementation.
Follow the user's requested scope when deciding whether to implement it.

Once work is implemented or superseded, move lasting usage and architecture
guidance into normal docs and remove the completed proposal text. Keep only
remaining work in a partially implemented proposal; Git preserves the history.
